# jawiki 全記事グラフ分割 PoC — 評価レポート(SUMMARY)

**検証課題**: 「実際の jawiki グラフは、内部結合が強く・外部結合が弱く・計算的に独立させやすい
単位(=「銀河」)に分割できるか?」

**総合判定: B(条件付きで有望)** — 条件は §9 に確定形で記載。

- データ: Wikimedia 公式ダンプ `jawiki` **2026-09-02 版**(SHA-256 は `PROVENANCE.json`)
  - SQL 4 ファイル: page 171MB / redirect 14MB / linktarget 141MB / pagelinks 800MB
  - pages-articles XML 4.7GB(本文リンク抽出用)/ categorylinks 176MB(カテゴリ純度用)
- シード: 42(Leiden / BFS サンプリング共通)
- ライブラリ: Python 3.11–3.13, numpy 2.4.6, scipy 1.17.1, pyarrow(pandas 3.0.6), python-igraph 1.0.0, leidenalg 0.12.0
- 計測環境: 小規模実験 = 2 vCPU / RAM 1GB のサンドボックス、フルグラフ = ローカル 32GB / Windows 11 / Python 3.13.11
- コマンド手順: README.md(工程別)/ LOCAL_SETUP.md(環境・取得・出版)

## 2. サブセット実験(小規模検証による方法論的知見)

10k–100k ノードの BFS サブセットで分割手法の当たりを付け、フルグラフ(§3 以降)に臨んだ。
独立性評価は内部エッジのみで行い、リーク(サブセット外へのリンク)は別建てで報告する
(サブセットは「グラフの切り身」でありコミュニティの合併体ではないため、リーク自体は
分割の失敗を意味しない)。

### 2.1 抽出方式とリーク率

| サブセット | 方式 | ノード | 内部エッジ(有向) | 外部へ(out) | 外部から(in) | **leak_out** |
|---|---|---|---|---|---|---|
| idwin_late_10k | ページID末尾 1 万 | 10,000 | 28,229 | 554,316 | 207,723 | **95.2%** |
| bfs_geo_30k | 地理系 12 種記事から out-link BFS(cap40, ≤3hop, in次数>1万を除外) | 30,000 | 1,662,557 | 5,905,734 | 14,617,961 | 78.0% |
| bfs_mixed_30k | 混合理系/文化系 10 種記事から同 BFS | 30,000 | 1,376,803 | 4,829,817 | 11,854,813 | 77.8% |
| bfs_geo_100k | 地理系 BFS(cap60, ≤4hop) | 100,000 | 6,874,293 | 13,286,361 | 26,024,757 | **65.9%** |

- **ID 窓抽出はコミュニティ評価に使用不能**(内部構造がほぼ無い: crossF=0.002、§2.3 の表)。対照実験としてのみ有効。
- **規模を上げるとリーク率は低下**(78%→66%)。境界効果の縮小 = 全体グラフではさらに改善が見込める(実際に §3 で crossF 0.276 まで低下)。

### 2.6 ハブ抑制手法の比較(最重要の手法知見)

| 手法 | 結果 |
|---|---|
| hub ノード削除(in次数>1k/3k を落とす) | **グラフ破砕**(コミュニティ中央値=1)。スター型銀河(Stub↔地域ハブ)のスポークが切れる |
| 次数予算 both モード(両端 rank<B のみ保持) | **同様に破砕**(30k: 29%保持で中央値1、100k: 33%保持で中央値1) |
| **smart モード**(低次数ノードの辺は常時保持、高次数↔高次数のみ間引き) | **構造を保持**(69%/63.5% 保持、中央値 549/1,474)。銀河内部は温存し「銀河間高速道路」のみ剪定 |
| エッジ重み 1/(log d_u・log d_v) | ほぼ無効果(重みレンジが 2.4 倍しかない) |
| エッジ重み 1/(d_u・d_v) | **悪化**(cross_frac 0.38–0.51)。ハブ辺は本物のコミュニティシグナルも運ぶ |

### 2.7 境界ノード

- boundary_node_ratio(1 本でもコミュニティ間エッジを持つノード割合): geo100k p50=**0.984**、mixed p50=0.827、boundary_any(サブセット外リンク含む)= **ほぼ 100%**。
- 平均次数 69–94 の稠密グラフでは「境界を全く持たない銀河」は存在しない。**境界はアンカー/集約重みで扱い、クロスリンク全量を銀河ローカルジョブに持たせない設計が必須**であることの定量根拠。
- ただし容量の観点: 境界「エッジ数」比率(out_ratio)は 0.24–0.42(100k, res0.5–1.0)であり、境界情報は「コミュニティあたり隣接コミュニティ要約 + 代表アンカー点」に圧縮可能(隣接コミュニティ数は top ペア構造から見て各コミュニティ数十程度)。

### 2.8 階層化(L2)

- mixed 30k(L1=res2.0 で 27 コミュニティ → L2 Leiden):**4 実クラスタ + 1 孤立**。out_ratio2 = 0.222 / 0.292 / 0.424 / **0.051**(小クラスタ)。L1 の out_ratio p50=0.532 から **L2 で 0.22–0.29 へ大幅低下** → 上位にまとめるほど独立性が上がる=階層化は機能する。
- geo 30k: L2=4 クラスタ、out_ratio2 0.36–0.49(L1 0.63 から改善するが高い)。
- geo 100k raw res0.5: L1 が既に粗すぎて L2 退化(1 クラスタ)。**階層評価は「細かい L1(res≥2)→ L2 集約」の順で行うべき**。

## 3. 全グラフのマクロ構造(一括 Leiden と解像度限界)

フルグラフ(1.45M ノード / 無向一意 108.2M エッジ)の一括 Leiden(ローカル 32GB):

| 項目 | 値 |
|---|---|
| 無向一意エッジ(dedup 後) | **108,164,716**(有向 142.4M、相互リンク率 ~24%) |
| res=0.5 / 1.0 / 2.0 のコミュニティ数 | 494 / 499 / 512(**resolution がほぼ効かない**) |
| modularity(res=1.0) | **0.6410**(res0.5: 0.7056、res2.0: 0.5856) |
| res=1.0: crossF / 最大シェア / top5 シア | 0.276 / 16.2%(246,097 ノード)/ 55.9% |
| res=1.0: out_ratio p50(実質コミュニティ)/ conductance p50 | **0.278** / 0.162 |
| サイズ分布の真実 | 499 のうち **~436 は孤立ノードのシングルトン**(size p50=1 の正体)。実効コミュニティは **~63 個**、平均 ~24k ノード |
| L2(res=1.0 のまま)| 441 クラスタ / 最大 70.2% / modL2 0.105 → L1 が粗すぎて機能せず |

**診断**: モジュラリティ最適化の**解像度限界**(√2m ≈ 14,700 ノード未満を分解不能)と**ハブ支配**(平均次数 143)により、一括分割では銀河サイズ(数百〜数千)のコミュニティは得られない。これはサブセット実験の知見(ハブが構造を支配)のフルスケールでの再確認であり、**2 段階分割(マクロ一括分割 → マクロ内再帰分割)が「必要」であることが実証された**(方式の失敗ではない)。マクロ構造自体は強く健全(crossF 0.276、実質コミュニティの out_ratio p50 0.278、conductance p50 0.162)。

**対策(実装済み)**: `run_full_leiden.py subdivide` — 各マクロコミュニティの誘導部分グラフ内で Leiden を再帰実行し、全断片が max_galaxy 以下になるまで分割(解像度限界は部分グラフ規模が縮むため回避される)。回帰テスト `tests/test_subdivide.py` 付き。

## 5. 銀河独立性の頑健性: 剪定実験

**既存銀河分割 × smart 剪定グラフ評価**: prune B=40 → 108,164,716 → **57,346,660 辺(53.0% 保持、平均次数 75.6)**、114 秒。同一分割(res1_sub)の評価: crossF 0.578(生 0.568)、oR p50 **0.715**(生 0.738)、oR<0.5 ノードシェア 8.3%(生 7.7%)。

**剪定グラフで再分割**: detect res1.0(igraph 構築 622s + Leiden 116s)→ C=499、mod 0.629、**largest 24.5%(371,065 ノードのブロブ化)**。subdivide 83s → 実効 1,494 銀河(中央値 320.5)。評価: crossF 0.574、oR p50 **0.722**。L2: K=457、modL2 0.422、oR2_w **0.361**(生 0.391 から微改善)。

**結論**:
1. **銀河の out_ratio ≈ 0.72±0.02 は剪定・再分割に対して頑健** → 分割手法の artifact ではなく、トランスクルード膨張したリンクグラフ自体の性質。銀河独立性のレバーは剪定ではない
2. 副次発見: smart 剪定は**マクロ分離を弱める**(largest 16.2%→24.5%)。ハブ間「高速道路」はマクロコミュニティの境界維持にも寄与していた
3. 剪定の価値は**レイアウト/描画コスト削減**(-47% 辺)と L2 の微改善として残る
4. → リンク意味論そのものを変える**本文リンクグラフ(§6)が銀河独立性の決定的実験**となる

## 6. 本文リンクグラフ(テンプレート由来リンクの除去)

### 6.1 実装と部分検証

`wu/xmlparse.py` + CLI `body-edges`: pages-articles XML から記事自身の wikitext 内の [[リンク]] のみを抽出(トランスクルード由来はソースに含まれないため自動除去)。コメント/nowiki/includeonly 除去、`--strip-refs` オプション、別名/アンカー/ucfirst/ns prefix/リダイレクト解決/記事内 dedupe 対応、チェックポイント resume 付き。dedup は `--edges-in/--out-name` で汎用化。合成 XML テスト(tests/test_bodylinks.py)全経路パス。

部分検証(pages-articles1 = pageID 1–114,794 の最古記事群 403MB、生存者バイアス強):
59,617 記事 → **7,890,263 本文エッジ**、193 秒(~280 pages/s)。同一記事の pagelinks 次数 vs 本文次数の対比較(`scripts/compare_body_vs_pagelinks.py`、~44k 記事)で膨張比 p50 ×1.42 / p90 ×4.67 / p99 ×17.0、Pearson 0.84 / Spearman 0.80。top 膨張(化学に関する記事の一覧、扇千景 ×7.4、アメトーーク! ×5.0 等)が**トランスクルード navbox =「銀河間高速道路」の正体**であることを実証。

### 6.2 フルラン実測(XML 4.7GB、DL 56分 + 処理 ~25分)

| 項目 | 値 |
|---|---|
| 本文エッジ(有向) | **71,083,593**(記事 1,516,321、平均本文 out 次数 **46.9**、826 秒) |
| 本文エッジ(無向一意) | **63,167,471**(pagelinks 比 **-42%**。相互リンク率 11.1% vs pagelinks 24.1%) |
| detect res1_body | C=1,522、mod **0.5361**、largest **19.1%**、実効マクロ ~28 + **孤立シングルトン 1,494** |
| subdivide | → 2,394(実効 **900** + 1,494)、中央値 **1,133**、93 秒 |
| metrics res1_body_sub | crossF **0.709**、oR p50 **0.850**(生グラフ銀河の 0.568/0.738 より**悪化**) |
| cluster L2 | K=1,512、largest 22.8%、modL2 0.394 |
| 孤立記事 | 436(全リンク)→ **1,494**(本文)= pure_template 記事の存在 |

**pagelinks vs 本文次数の膨張率(フル対比較)**: pagelinks outdeg p50=46/p90=222 vs body p50=28/p90=93。**膨張率 p50=×1.23**(中央値記事は僅か)/ p90=×4.99 / p99=×22.8 = **ヘビーテール**(地理 Stub・芸能・年表に集中)。pure_template(本文 0・pagelinks 50+)= **115 記事**。平均 out 次数 94.0 vs 46.9、Pearson 0.736 / Spearman 0.747。→ 記事ズーム時の間引きは「本文リンク優先」ポリシーが有効。

### 6.3 解釈(「本文リンクなら銀河が独立する」仮説の単純形は反証)

1. **ナビボックスの半分は「銀河内セメント」だった**: navbox は主題ベース(「長野県の市町村」等)で同主題記事を密結合させていた。除去すると modularity 0.641→0.536 に低下
2. **本文リンクは「連想的」**: 記事本文は言及先(人物・地名・事件・概念)へ主題横断的に飛ぶ。銀河 oR は 0.738→0.850 へ悪化
3. **総合結論**: 「銀河サイズ(数百〜数千)で外部結合が弱い単位」は、生/剪定/本文の**どのリンク意味論でも存在しない**(oR 0.71–0.85)。一方マクロ構造は一貫して強い(生 crossF 0.276)。これは Wikipedia の編集行動の本質であり、方式の失敗ではない
4. **設計含意(判定 B の条件が確定)**:
   - 銀河 = **アンカー制約付きレイアウト単位**(自由バッチではない)— 境界アンカー設計の必須性が最終確定
   - 銀河の**意味付け(命名・色・UI グループ化)はカテゴリ情報から**行う(→ §7 で検証済み)
   - リンク意味論の使い分け: レイアウト力 = 生/剪定グラフ、意味的接続の描画 = 本文グラフ

## 7. カテゴリ純度と銀河の命名

**categorylinks 解析(フル)**: 12,873,354 行(page 11,975,430 / subcat 866,488 / file 31,436、cl_from 非記事 1,035,896)→ **記事×カテゴリ対 10,939,524**(記事あたり ~7.2)、カテゴリ総数 **540,651**。67 秒。

**純度(res1_sub)**: 生(top1_share)はノード重み平均 0.477 だが、top カテゴリは「すべてのスタブ記事」「存命人物」「ウィキデータにある座標」等の**保守用メタカテゴリが支配**(=テンプレートハブのカテゴリ版)。→ **purity v2**: `--max-cat-freq`(既定 2 万)超のカテゴリを命名から除外し tf-idf で `name` 列を生成。フィルタ後 top1_share mean **0.301**(p50 0.245 / p90 0.623)。**nameable_share: ノード比 37.8% / 実効コミュニティ比 63.8%**(閾値 0.30)。純度は銀河サイズと逆相関(最大級 8–10k 銀河は 0.06–0.48)。本文銀河の nameable は 31.2%/44.7% とやや低く、学術系(数学 0.754、バスケットボール 0.778)が最も純度が高い。中頻度の技術系カテゴリ(座標タグ誤り/allcinema識別子/Titlestyle 等)は頻度フィルタをすり抜けるため、**カタログ側でブラックリスト+代表記事フォールバックの命名キュレーション**を追加(→ §8)。

**rep_titles による銀河の実名確認(res1_sub top12)**: メディア産業(YouTube/オリコン/DVD)、**年代(2007年…、oR 0.965)**、北海道地理、神道(神社/神道/日本書紀)、サッカー(oR 0.590)、**学術識別子(DOI/ISSN/PubMed)**、出版(東京/岩波書店/朝日新聞社)、**元号(昭和/平成/大正、oR 0.924)**、理工(物理学/技術/工学)、分類学(学名/目/科)。
→ **年代・元号・汎用ハブ・識別子は oR 0.92–0.97 の「媒介銀河」を形成**(銀河間物質の実証)。ビューアでは特別描画(半透明の星間ガス/バンドルハブ)が適する。主題銀河(サッカー 0.59、メディア 0.72 等)は命名・色付け可能。

## 9. 総合判定: **B(条件付きで有望)**

### 肯定的サイン(観測されたもの)
- ✅ 数百〜数千ノードのコミュニティが多数(銀河サイズ中央値 279、p95 4,533、max 9,828)
- ✅ 最大コミュニティのシェアが極端でない(銀河層 0.65%、マクロ層 16.2%)
- ✅ modularity 0.51–0.65(強い構造)
- ✅ コミュニティの意味的一貫性(テーマ・カテゴリと良好に対応、§2.4)
- ✅ **規模拡大で外部結合率が低下**(サブセット oR 0.63@30k → フルグラフマクロ 0.278、leak 78%→66%→フル)
- ✅ 上位クラスタ化で out_ratio が低下(階層グラデーション 0.74 → 0.39 → 0.28、§4)
- ✅ コミュニティ間エッジが単一ハブ「ノード」に集中しているわけではない(集中しているのは年代・政治・日付などの「ハブ的コミュニティ」— 前処理で対処可能)
- ✅ 銀河→マクロの包含・ペア集約が完全自己整合(containment 0 違反、重み合計一致、§8)

### 危険サイン(観測されたもの)
- ⚠️ **銀河レベルの out_ratio は意味論に依らず高い**(生 0.74 / 剪定 0.72 / 本文 0.85)。「銀河=完全独立バッチ」は不可能で、境界アンカー前提の設計が必須(§4/§6)
- ⚠️ boundary_node_ratio ≈ 0.83–0.99 → 境界は**要約表現**(隣接コミュニティ重心 + 集約重み + アンカー)が必須(§2.7)
- ⚠️ ドメインにより銀河の「鮮明さ」が違う(地理系は行政階層・鉄道網・年表で密に相互連結)
- ⚠️ ハブ記事(年・日付・ISBN・郵便番号・地理座標系)が次数を支配 → smart 剪定 + 媒介銀河の特別扱いなしではコミュニティがハブに引きずられる
- ⚠️ エッジ総数が想定の 2 倍(142M 有向)→ 描画・配信設計の予算はこの実測前提

### 条件(確定形)

1. レイアウト用グラフは「smart 次数予算剪定 + 年代/元号/日付/一覧/学術識別子などの**媒介銀河・媒介ハブの特別扱い**(display_class=medium の特別描画)」を必須とする
2. 銀河間リンクはローカルジョブに全量渡さず、**集約重み + 境界アンカーに圧縮**する(銀河 = アンカー制約付きレイアウト単位)
3. 階層は「細かい L1 → L2 集約」の**ボトムアップ**で構築する(一括 Leiden の解像度限界を subdivide で回避)
4. 銀河の**意味付け(命名・色・グループ化)はカテゴリ情報から**行う(リンク分割は「形」、カテゴリは「意味」。nameable_share はノード 37.8%/コミュニティ 63.8% でフォールバック命名込みで実用)
5. **リンク意味論の使い分け**: 構造決定・レイアウト力 = 生(pagelinks)グラフ、意味的接続の描画・記事ズームの間引き = 本文リンクグラフ

フルグラフ規模での検証(条件 3 の前提)はローカル 32GB で完了済み(§3–§8)。
